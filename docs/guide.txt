### The project I'd recommend

## **Fuel Transport Data Quality & Analysis Dashboard — Zambia**

Build a **small fictional dataset of petroleum product movements** and create a pipeline that cleans it, identifies data-quality problems, analyses transport costs/distances, and presents the results in a dashboard.

**Important:** label it clearly as a **portfolio/synthetic dataset**. Don't claim that your calculations represent ERB's actual UPP model.

### What it would look like

Imagine you have 200–500 fictional records like:

| Date       | Oil Marketing Company | Depot  | Product | Destination | Volume (L) | Distance (km) | Claimed Distance | Transport Cost |
| ---------- | --------------------- | ------ | ------- | ----------- | ---------: | ------------: | ---------------: | -------------: |

# The actual project

### 1. Data cleaning — Python/Pandas

Create `raw_data.csv`.

Then write:

`data_cleaning.py`

It should:

```text
Raw data
   ↓
Remove duplicates
   ↓
Standardise names
   ↓
Handle missing values
   ↓
Validate numerical fields
   ↓
Flag suspicious records
   ↓
Clean dataset
```

For example:

```python
df["product"] = df["product"].str.strip().str.title()

df = df.drop_duplicates()

df["volume_litres"] = pd.to_numeric(
    df["volume_litres"],
    errors="coerce"
)

df["distance_km"] = pd.to_numeric(
    df["distance_km"],
    errors="coerce"
)
```

Then create a **data quality report**:

```text

Duplicate records:            8
Missing distance:            11
Invalid volume:               3

High-cost anomalies:          9
Clean records:              302
```

That alone maps extremely well to:

and

> "reconcile datasets and identify anomalies, inconsistencies, duplicate records..."

# 2. Add a small SQL database

Since the advert specifically says SQL is an advantage, put the cleaned data into **SQLite or PostgreSQL**.

You don't need anything complicated.

Have tables such as:

```text
companies
depots
shipments
destinations
```

Then write perhaps **5 SQL queries**.

For example:

### Total volume by product

```sql
SELECT product,
       SUM(volume_litres) AS total_volume
FROM shipments
GROUP BY product;
```

### Average transport cost by destination

```sql
SELECT destination,
       AVG(transport_cost) AS avg_cost
FROM shipments
GROUP BY destination
ORDER BY avg_cost DESC;
```

### Suspicious distance claims

```sql
SELECT *
FROM shipments
WHERE ABS(claimed_distance_km - reference_distance_km) > 20;
```

Now you're demonstrating **database management + SQL + analytical thinking**.

# 4. Add one analytical question

This is what turns it from **"I made a dashboard"** into **"I'm a data analyst."**

For example:

### **Which routes require further investigation?**

Calculate something like:

**Cost per litre**

$$
Cost\ Per\ Litre = \frac{Transport\ Cost}{Volume}
$$

and perhaps:

**Cost per litre-km**

$$
Cost\ Per\ LitreKm =
\frac{Transport\ Cost}{Volume \times Distance}
$$

Then flag routes that are unusually high compared with other routes.

You could conclude:

> "Three routes had substantially higher cost-per-litre-km values than the dataset average and were flagged for further investigation."

Notice the wording: **flagged for investigation**, not "fraudulent" or "incorrect." That's much more professional.
